ШАГ 6. ГЕНЕРАЦИЯ ТЕСТОВ

Следуй этим правилам для каждого ФТ из functional-req.md:

6.1. Минимальное покрытие:
- Каждое обязательное ФТ (обязательность из БТ) должно иметь МИНИМУМ один тест
- Каждое опциональное ФТ (помечено "Опциональное") — тест опционален, но желателен
- Альтернативные потоки из БП или use-cases.md также должны иметь тесты (негативные сценарии)

6.2. Структура теста:

describe('ФТ-XX: [название из functional-req.md]', () => {
  let originalFetch;
  
  beforeEach(() => {
    // Настройка DOM перед каждым тестом
    document.body.innerHTML = `
      <div id="app">
        <!-- минимальная структура, необходимая для теста -->
      </div>
    `;
    
    // Сброс моков
    jest.clearAllMocks();
  });
  
  afterEach(() => {
    // Восстановление оригинальных функций
    if (originalFetch) global.fetch = originalFetch;
  });
  
  test('должен [ожидаемое поведение из ФТ]', () => {
    // Arrange — подготовка данных
    // Act — действие пользователя или вызов функции
    // Assert — проверка результата
  });
});

6.3. Типы тестов в зависимости от функциональности:

ЕСЛИ ФТ связано с пользовательским вводом (кнопки, формы):
- Имитируй клики: button.click()
- Имитируй ввод: input.value = 'текст'; input.dispatchEvent(new Event('input'))
- Проверяй содержимое DOM: expect(display.textContent).toBe('5')

ЕСЛИ ФТ связано с вычислениями (калькулятор, конвертер):
- Импортируй функцию (если экспортирована) или создай экземпляр класса
- Проверяй результат выполнения

ЕСЛИ ФТ связано с API (конвертер валют):
- Мокай fetch: jest.spyOn(global, 'fetch').mockResolvedValue({ json: () => ({ rate: 75.5 }) })
- Проверяй, что fetch вызывался с правильным URL

ЕСЛИ ФТ связано с хранением (localStorage):
- Мокай localStorage: jest.spyOn(Storage.prototype, 'getItem').mockReturnValue('...')
- Проверяй, что setItem вызывался с правильными аргументами

6.4. Разбиение по файлам:

Если количество ФТ меньше 10:
- Один файл: output/tests/functional.test.js

Если количество ФТ от 10 до 20:
- Разбей по доменам: output/tests/calculator.test.js, output/tests/storage.test.js, output/tests/ui.test.js

Если количество ФТ больше 20:
- Один файл на модуль из архитектуры: output/tests/[module_name].test.js

6.5. Импорт тестируемых функций:

ЕСЛИ код использует export:
- Добавь в начало тестового файла: const { functionName } = require('../../src/path/to/file.js');

ЕСЛИ код не использует export:
- Скопируй тестируемую функцию в тестовый файл с комментарием: // Функция взята из src/core/calculator.js
- НЕ копируй весь файл — только минимально необходимые функции

ПРИМЕР ТЕСТА ДЛЯ API (конвертер валют):

describe('ФТ-03: Получение курса из API', () => {
  let mockFetch;
  
  beforeEach(() => {
    mockFetch = jest.spyOn(global, 'fetch').mockResolvedValue({
      json: () => Promise.resolve({ rate: 91.5 })
    });
  });
  
  afterEach(() => {
    mockFetch.mockRestore();
  });
  
  test('должен загружать курс USD/RUB при загрузке страницы', async () => {
    // Импортируем модуль, который вызывает fetch
    const { loadRates } = require('../../src/api/currency.js');
    await loadRates();
    expect(mockFetch).toHaveBeenCalledWith('https://api.exchangerate.com/usd-rub');
  });
});
