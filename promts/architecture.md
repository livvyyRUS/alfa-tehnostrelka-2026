4.2. Требования к модулям:
- Количество модулей: от 3 до 7
- Каждый модуль должен иметь чёткую ответственность (не "всякое", не "утилиты", если только это не отдельный модуль utils)
- Каждый модуль должен ссылаться минимум на одно ФТ (поле "Связанные ФТ")
- Планируемые файлы должны быть конкретными путями, не более 5 файлов на модуль
- Зависимости не должны образовывать циклов (A зависит от B, B не должен зависеть от A)

4.3. Варианты архитектур в зависимости от требований:

Правила выбора:
- Если в ФТ есть операции с внешним API (получение курсов валют, отправка данных) → выдели отдельный модуль API Client
- Если в Features указано "хранить в localStorage" или БТ содержит сохранение между сессиями → выдели модуль Storage
- Если приложение имеет более 3 экранов/состояний или требует сложной логики переходов → выдели модуль State/Router
- Если количество ФТ меньше 10 → допустима простая 3-модульная архитектура (UI, Logic, Data/Storage)
- Если много альтернативных потоков в UC → выдели модуль Error/Exception Handling

4.4. Соглашение об именовании модулей:
- UI модуль: `ui`, `components`, `view`
- Логика: `core`, `logic`, `controller`, `calculator` (по домену)
- Данные: `storage`, `data`, `api`, `state`
- Утилиты: `utils`, `helpers`

# Архитектура приложения

## 1. Общий подход
Одностраничное приложение (SPA) на чистом JavaScript без серверной части. Вся логика выполняется в браузере, данные хранятся в localStorage.

## 2. Стек технологий
- HTML5
- CSS3 (Flexbox/Grid)
- Vanilla JavaScript ES2020
- Без сборщиков (для простоты)

## 3. Модульная структура

### Модуль 1: UI (Пользовательский интерфейс)
**Ответственность:** Отрисовка кнопок, дисплея, отображение результата
**Входящие зависимости:** Controller
**Исходящие зависимости:** — (нижний уровень)
**Связанные ФТ:** ФТ-01, ФТ-05, ФТ-07
**Планируемые файлы:**
  - src/ui/display.js
  - src/ui/buttons.js
  - src/ui/render.js

### Модуль 2: Controller (Логика вычислений)
**Ответственность:** Обработка нажатий, выполнение арифметики, проверка ошибок
**Входящие зависимости:** UI
**Исходящие зависимости:** Storage
**Связанные ФТ:** ФТ-01, ФТ-02, ФТ-03, ФТ-04
**Планируемые файлы:**
  - src/core/calculator.js
  - src/core/validator.js
  - src/core/errorHandler.js

### Модуль 3: Storage (Хранение данных)
**Ответственность:** Сохранение и загрузка истории в localStorage
**Входящие зависимости:** Controller
**Исходящие зависимости:** — (нижний уровень)
**Связанные ФТ:** ФТ-06 (история), ФТ-08 (очистка)
**Планируемые файлы:**
  - src/storage/history.js
  - src/storage/state.js

## 4. Потоки данных
1. Пользователь нажимает кнопку → UI вызывает метод Controller с данными
2. Controller выполняет вычисление → обращается к Storage при необходимости
3. Controller возвращает результат в UI
4. UI обновляет дисплей

## 5. Учёт НФТ
- НФТ-01 (отклик <200 мс): Все вычисления синхронные, без лишних DOM-операций
- НФТ-02 (кросс-браузерность): Используем стандартный ES6 без полифиллов
- НФТ-03 (сохранение сессии): Модуль Storage синхронно пишет в localStorage

## 6. Ограничения и допущения
- Предполагаем современный браузер с поддержкой ES6 и localStorage
- Без серверной части
- Максимальный размер истории — 10 записей (по БТ-02)
