ШАГ 5. ГЕНЕРАЦИЯ КОДА ПО ПЛАНУ – ПОЛНЫЙ ЦИКЛ

Следуй строго порядку из file-manifest.json (поле generation_order). Каждый файл из этого списка ДОЛЖЕН быть создан. Пропускать элементы generation_order категорически запрещено.

Для каждого файла из generation_order выполни следующие шаги:

5.1. Проверка зависимостей:
- Найди описание файла в file-manifest.json (в modules или non_module_files)
- Убедись, что все файлы из depends_on уже сгенерированы. Если какого-то файла ещё нет, НЕ останавливайся с ошибкой — вместо этого сначала создай недостающие зависимости (рекурсивно, придерживаясь порядка из generation_order), а затем вернись к текущему файлу.

5.2. Правила генерации JavaScript (app.js или модульные файлы):
- Используй ES6 синтаксис (const, let, arrow functions, template literals)
- Добавляй JSDoc комментарии для всех публичных функций
- Реализуй все ФТ, указанные в поле implements_ft для этого файла
- Следуй exports/requires_from из манифеста
- Обрабатывай ошибки (try/catch для async операций, валидацию входных данных)
- Если Features указывает на конкретные сообщения об ошибках — используй их

5.3. Правила генерации HTML (index.html):
- Семантическая вёрстка (header, main, footer при необходимости)
- Подключение всех CSS и JS файлов в правильном порядке (строго как указано в generation_order или зависимостях)
- Атрибут lang (из Features или по умолчанию "ru")
- Мета-тег viewport для мобильной адаптивности

5.4. Правила генерации CSS (styles.css или модульные стили):
- Используй CSS Variables для тем (если Features требует тёмную тему)
- Адаптивный дизайн (медиа-запросы для мобильных устройств)
- Классы по БЭМ или простой каскад

5.5. Учёт НФТ из non-functional-req.md:
- НФТ-01 (производительность): избегай лишних перерисовок, используй debounce для частых событий
- НФТ-02 (кросс-браузерность): проверяй наличие localStorage, используй стандартные API
- НФТ-03 (удобство использования): добавляй aria-атрибуты, фокус на кнопках

5.6. Учёт Features:
- Если Features содержит "тёмная тема по умолчанию" — body должен иметь класс dark-theme
- Если Features содержит локализацию — все тексты на указанном языке
- Если Features содержит конкретные названия — используй их

ШАГ 6. ЖЁСТКАЯ ВЕРИФИКАЦИЯ И ДО-ГЕНЕРАЦИЯ

После того как ты однократно прошёл по generation_order, выполни ОБЯЗАТЕЛЬНУЮ проверку полноты:

6.1. Выполни listdir рекурсивно в output/src/ (или всех необходимых поддиректориях).
6.2. Сравни полученный список файлов с полным перечнем, который должен быть создан согласно file-manifest.json. Учитывай относительные пути.
6.3. Если обнаружены отсутствующие файлы – НЕМЕДЛЕННО создай их, следуя правилам генерации из Шага 5. После создания повтори проверку (пункты 6.1-6.2) до тех пор, пока список созданных файлов не совпадёт полностью с ожидаемым.
